The problem

Finding internships is a data problem wearing a busywork costume.

Relevant postings are scattered across dozens of company ATS platforms, each with its own format and its own API. Finding the right ones means opening tab after tab, re-reading near-identical descriptions, and guessing at fit. The tedium is real, but the temptation to "automate" it with a bot that mass-applies is exactly the wrong fix — it floods recruiters and produces applications no human stands behind.

Apply Pilot treats discovery and triage as the actual problem, and keeps the human firmly in the loop for everything that matters.

The system

A pipeline that ends at a person, not a submit button.

Live postings are pulled from ATS platforms, normalized into one structured schema, ranked against the candidate profile with explainable scoring, and staged in a review workflow. Backed by 21 API route handlers across 7 UI pages, the whole flow is built around two hard rules: it never auto-submits applications, and it never invents candidate experience.

Technical challenges

The genuinely hard parts.

01

Normalizing many ATS APIs

Every ATS returns a different shape, vocabulary, and pagination model. Collapsing them into one clean, structured schema — without losing source fidelity — is most of the real work.

02

Ranking that explains itself

A score is only useful if you can see why. Rankings surface the signals behind them, so the candidate can trust — and override — the ordering instead of deferring to a black box.

03

Never fabricating experience

The system structures and matches what the candidate actually has. It prepares and organizes applications, but it does not invent skills, roles, or accomplishments to inflate fit.

04

A safe review workflow

Applications move through explicit review states and stop at a human decision point. There is no code path that submits on the candidate's behalf without an intentional action.

Engineering decisions

Choices, and what they cost.

01

Human-in-the-loop, never auto-submit

Why I chose it
Applications should be things a person actually stands behind — and it keeps recruiters from being spammed.
Alternative considered
A fully automated apply bot that submits on the user's behalf.
Tradeoff
Less "magic," more integrity. The product saves time on discovery and triage, not on accountability.
02

Explainable ranking over a black box

Why I chose it
Users trust and correct a ranking they can see reasons for; opaque scores get ignored.
Alternative considered
A single end-to-end model emitting an unexplained match score.
Tradeoff
More engineering to expose signals, but the output is auditable and correctable.
03

Normalize to one schema up front

Why I chose it
Everything downstream — ranking, review, UI — reads one clean shape instead of N messy ones.
Alternative considered
Handling each ATS format ad hoc throughout the app.
Tradeoff
A heavier ingestion layer, but far less complexity everywhere else and easy to add new sources.

Result

Where it stands.

Apply Pilot is in active development: ~7,200 lines of application source, 21 API route handlers, and 7 product pages spanning discovery, structured parsing, explainable ranking, and the review workflow. It's a working demonstration that "AI for job applications" can be genuinely useful without ever crossing the lines of auto-submitting or fabricating experience.
